Kafka

Case: order_created event

The student sees how asynchronous integration differs from REST request-response.

Business situation

After order creation, other systems need to react: delivery, notifications, analytics. Backend publishes an event into topic orders.events.v1.

Event example

{
  "event_id": "evt-0001",
  "event_type": "order_created",
  "request_id": "req-2026-0001",
  "order_id": "ord-10001",
  "customer_id": "usr-777",
  "created_at": "2026-06-18T12:00:00Z"
}

Student tasks

  1. Find event type and topic name.
  2. Explain why consumer can process event later.
  3. Explain why duplicate events are possible.
  4. Explain why event_id is useful.

Analyst takeaway

Kafka is not a direct answer like REST. It is a stream of facts. Requirements should describe event schema, delivery expectations and idempotency.
