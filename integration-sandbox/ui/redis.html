Redis

Case: cached order status

The student learns why cache exists, why it can be stale and what TTL means.

Business situation

Order status is read often. To reduce database load, backend stores a short-lived copy in Redis.

Key and value

Key:
order:ord-10001:status

Value:
{
  "order_id": "ord-10001",
  "status": "CREATED",
  "cached_at": "2026-06-18T12:00:05Z"
}

TTL: 60 seconds

Student tasks

  1. Compare status in REST response, database and Redis.
  2. Find a case where database status is newer than cache.
  3. Explain why user may see old status for a short time.
  4. Write a requirement for acceptable status delay.

Analyst takeaway

Cache improves speed, but creates consistency questions. Analyst should ask whether data must be real-time or near-real-time.
